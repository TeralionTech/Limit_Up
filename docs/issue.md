## Issue #1 — T30 第一次處置 (MARK-W='1') 改「分單下、總量設限」而非整檔封鎖

**狀態**: 計畫,未實作
**優先**: 高 (真金第一層防護 + 錯過可交易標的)

### 背景 / 問題
- 2026-08-24 5314(OTC)開盤預掛單被券商退:「全額處置股,預收或圈存不足」。
- 查原始 T30 檔:5314 記錄 `settype='0'`(非全額交割)、**`MARK-W='1'`**(第一次處置)。
- 現行 [t30.py](../t30.py) `parse_untradable` 判斷式為 `settype != "0" or mark_w == "2"`,
  **只認第二次處置 `'2'`,漏掉第一次處置 `'1'`** → 5314 沒進禁單 → 預掛單送出被退。
- 對照權威版 [../T30_extractor/extract_restricted.py](../../T30_extractor/extract_restricted.py):
  處置股 = **`MARK-W != '0'`**(1=第一次、2=第二次)。我們的條件跟參考版跑掉了 = bug。
- 影響有限:被退時 `a818a83` 的致命拒因關鍵字層(「預收」「全額」)已攔下,只送一筆就停、
  **沒有狂送單**,也沒買進 5314。屬第一層(預先擋單)漏接,非 spam 風險。

### 台股第一次處置的「條件式預收」規則 (為何不能整檔封鎖)
第一次處置**不一定全面預收**,採**條件式預收款券**:
- **單筆委託 達 10 張** → 該筆需 100% 預收。
- **多筆委託累計 達 30 張以上** → 需 100% 預收。
- 未達上述數量 → 維持一般交割(可正常下單)。

(第二次處置 MARK-W='2' 則是「每一筆委託都要 100% 預收」→ 等同下不了單 → 維持整檔封鎖。)

### 期望處理
分三類,取代現行「untradable 二分」:

| 類別 | 條件 | 處理 |
|---|---|---|
| **整檔封鎖 (untradable)** | `settype != '0'` (全額交割) **或** `MARK-W == '2'` (第二次處置) | 預掛/市價追一律跳過 (現行行為不變) |
| **條件式可下 (split-limited)** | `settype == '0'` **且** `MARK-W == '1'` (第一次處置) | **可下,但受量限制**(見下) |
| 一般 | 其餘 | 正常 |

**split-limited 標的的下單約束**(避開預收門檻):
- **每筆委託 < 10 張**(即 ≤ 9 張)。
- **當日該檔所有委託累計 < 30 張**(即 ≤ 29 張;跨預掛 + 市價追 + 重試全部相加)。
- 目標量若 > 單筆上限 → **拆成多筆**下(例 25 張 = 9 + 9 + 7)。
- 累計達上限後不再加單(等於該檔實際可搶量上限 29 張)。

### 待確認 / 邊界
- **門檻含不含界線**:規則寫「達 10 張」「達 30 張以上」= ≥ 觸發 → 安全值取
  每筆 ≤ 9、累計 ≤ 29(嚴格低於門檻)。若使用者接受剛好 =30 再議。
- **「多筆累計」是否含已撤單 / 被拒的委託**:券商計算基礎待查(保守假設:所有「送出」的張數都算,

  min(target 拆分, 9, 20%量, 禁現沖減半...) 的組合,需在下一版市價策略重寫一併定義。
- **處置股本來就分盤集合競價撮合**(非逐筆),市價搶單策略對它幾乎無效 → split-limited
  實務上主要靠「漲停價預掛限價單」;要確認這個量限制值不值得為處置股做(vs 直接跳過)。
